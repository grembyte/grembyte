# Code review 2026-10-29

A review of the whole code base at commit `c5bc21c`, in five parts: hooks and watch,
core and platform, engines and features, database and UI, and the documentation against
the code. Findings were checked by reading the code paths; those marked *verified* were also
reproduced or checked again by hand. Line numbers refer to `c5bc21c`.

Status: **fixed** (with the change that fixed it), **open**, or **partly fixed**.

## Test suite

On the first run the suite aborted with a core dump in
`test_pointer_dialog_survives_a_restart_of_the_program`; the next run passed (496 tests).
Cause: windows released finished `QThread` workers in a slot of `finished`, which Qt emits
before the thread has ended (finding 7). **Fixed**; after the fix, three full runs passed.

## Critical

1. **Repatching into a new cave leaves a stale `patchedHex`** (`hermes/hooks/engine.js`,
   `repatchSite`), *verified*. After the short jump moved to a new cave, the site reported
   "changed" forever, was never patched again, and `uninstallSite` did not restore the
   original code, so the game jumped into the freed trampoline after unload. Affects exactly
   the anti-tamper case repatching was built for. **Fixed**: `patchedHex` is read again
   after patching; test `test_repatch_into_a_new_cave_is_restored_on_removal`.
2. **ptrace backend can freeze the game** (`hermes/core/ptrace_engine.py:257-416`). A thread
   whose `_arm` fails (e.g. EINVAL for an unaligned watchpoint, common in 32-bit Wine games)
   is dropped from `_armed` but stays stopped. `_detach_all` takes the first stop of a thread
   for its own SIGSTOP whatever it is; the real SIGSTOP then arrives after the detach and
   stops the whole game. Foreign signals (Wine's suspend SIGUSR1, Mono's GC signal) are
   swallowed in `_reprogram`. A clone's birth stop can be reported before the parent's
   clone event, which hangs `_on_clone` in `waitpid`. **Fixed**: one way to halt threads
   (`_stop_threads`) for re-arming and detaching that counts only the SIGSTOP it sent,
   delivers the target's own signals, acknowledges watchpoint traps and takes in threads
   born meanwhile; a thread is taken in from its first stop, whichever comes first; a
   SIGTRAP without a watchpoint bit (int3, single step) reaches the target; a thread
   whose registers cannot be written goes on; `waitpid` keeps to this thread's tracees
   (`__WNOTHREAD`); unaligned watchpoints are refused beforehand
   (`watch_alignment_error`). With the old code the test target was left stopped
   (state T) after every detach. Tests `test_ptrace_watch_keeps_signals_and_new_threads_of_the_target`,
   `test_ptrace_hooks_changing_keep_signals_and_new_threads`,
   `test_unaligned_addresses_take_no_watchpoint`.
3. **ptrace gadget loader** (`hermes/core/wine_gadget.py:381-660`). The other threads keep
   running during `LoadLibraryW` although the docstring says otherwise; `waitpid(-1, …)`
   can reap foreign children and tracees; stop signals other than SIGCONT are discarded
   while the borrowed thread runs; on a timeout the registers are restored while the thread
   may still hold the loader lock. **Fixed**: the other threads keep running (stopping
   them could stop one holding a lock LoadLibraryW needs) and are serviced the whole time
   like in the ptrace engine; threads that hit an `int3` of the loader are rewound and kept
   stopped until it is gone, also late ones; new threads are traced from birth; signals
   pending from the attach are delivered later; the borrowed thread gets its own signals;
   on a timeout it is left in its call, untouched. With the old code the native test
   scenario hung. Test `test_a_borrowed_thread_calls_and_the_others_keep_their_signals`
   (a native process, `answer()` in place of `LoadLibraryW`). Not yet tried in a real
   Proton game.
4. **Hook agent unloads while threads may still be in its code** (`engine.js:3083`,
   `engine.py:419`). `dispose()` sleeps before `removeHook`, then Python unloads the script
   at once; threads inside a trampoline or waiting in `jsBefore` return into freed memory.
   **Fixed (defensively)**: trampolines count the threads between their before and after
   callback (`lock inc`/`lock dec`); `dispose` waits for that count to reach zero (up to
   2 s, `Thread.sleep` lets threads waiting for the agent's lock in), then 20 ms for the
   few instructions outside the count, and reports what is left. The crash could not be
   reproduced with the old code (25 rounds under load); test
   `test_stopping_hooks_while_a_thread_writes_through_them`. A thread inside the bytes
   being patched when a hook is installed still crashes, as with any inline hook.
5. **Mono trace frees buffers early** (`hermes/features/trace.js:323`), *verified*. `stop()`
   kept only the CModule in `retired`; `state`, `counts` and `events` were freed by the GC
   while a callout could still write to them. `begin` did not clear the events of an earlier
   scenario. **Fixed**: the whole trace is retired, events are cleared before a scenario.
   A callout that saw the old phase at that very moment can still write one event; closing
   that needs an in-flight counter in the C code as in the native trace.
6. **Switching to another process keeps the scan state** (`hermes/ui/main_window.py:2094`),
   *verified*. Results, `previous_results` and a running scan of process A stayed; the next
   scan compared A's values with B's memory. **Fixed**: `_stop_scan_and_refresh()` for
   detach and switch, which also disconnects workers whose results are still queued; test
   `test_scan_of_the_previous_program_is_cleared_on_a_switch`.
7. **`QThread` lifetime** (seven places in `hermes/ui/widgets/`), *verified*. The last
   reference was dropped in a slot of `finished`; `closeEvent` waited for four of eight
   worker registries only. **Fixed**: `hermes/ui/workers.py` keeps workers until their
   thread has ended and stops all of them on close; tests in `tests/test_workers.py`.

## Medium

8. **Database schema evolution** (`hermes/db/engine.py:36-80`). `add_missing_columns` adds
   nullable columns only and skips NOT NULL ones; a legacy `data/hermes.db` with the old
   `addresses` table (`label`, `address` as text, no `process_id`) is copied and stays
   broken. `PRAGMA foreign_keys` is never set, so `ondelete=CASCADE` has no effect.
   **Fixed**: required columns are added with the model's default or an empty text where
   that keeps old rows usable; a table that cannot be used otherwise (a required column
   without a sensible placeholder, a stale required column, text where the model stores
   numbers) is kept as `<name>_old` and created anew, without rewriting other tables'
   foreign keys. Foreign keys are on for every connection. Rows in a set-aside table are
   not migrated. Test `test_init_db_sets_aside_a_table_of_the_first_versions`.
9. **Scanner: changing the type between scans** (`hermes/core/scanner.py:547`). Previous
   values are cast numerically instead of read again from their bytes, and auto results
   with several types at one address give duplicate rows. The refresh (`scanner.py:717`)
   keys values by address only, so rows of different types at one address show the same
   value. **Fixed**: previous values are read again from their bytes (a narrower type from
   the low bytes); candidates whose wider type has unknown bytes are kept only for scans
   that need no previous value; each address is compared once; refreshed values are keyed
   by address and type. Still open: after an "unknown initial value" scan (a memory
   snapshot) a newly chosen type is ignored.
10. **Pointer scan assumes 8-byte pointers** (`hermes/core/pointer.py:41,110,175`): no chains
    in 32-bit games. **Fixed**: `pointer_size(pid)` (32-bit ELF programs and 32-bit Wine
    programs, kept per process start) is used by the scan and by `resolve_chain`.
11. **Gadget download without integrity check, not atomic** (`wine_gadget.py:242`). A
    truncated file stays and fails with "LoadLibraryW returned NULL" from then on.
    **Fixed**: the download is checked against the SHA-256 GitHub lists for the release
    asset (no gadget is used if the release cannot be read), must be a PE image of the
    right machine type, and is written to a `.part` file that replaces the target.
12. **Hook ids collide** (`hermes/hooks/ptrace_hook.py:85`): ptrace hooks count from 1 per
    worker, method hooks use `HookWorker._ids`; both share one table in the hooks panel.
    **Fixed**: the ptrace worker takes its ids from `HookWorker._ids` too.
13. **Method monitor: module-wide `changes`** (`hermes/features/monitor.js:1192`). A
    transform that calls game code releases the JS lock; a nested or parallel `hookBefore`
    replaces `changes`, and the outer hook fails with a TypeError. **Fixed**: change lists
    per thread, as a stack for nested hooks.
14. **Native trace** (`hermes/features/native_trace.js:341, 617-643`): modules loaded after
    the inventory are not excluded from Stalker; the quiesce loop in `begin` has no timeout
    and no fence between its store and load. **Partly fixed**: the modules are listed
    again when the trace starts; the phase is set by a locked add in C (`set_phase`), and
    `begin` gives up after 2 s. Modules loaded during the trace stay unexcluded: a module
    observer that excluded them while threads were followed made Baldur's Gate and Dark
    Souls III crash under Proton (2026-10-29) and was removed; Stalker's exclusions are
    only changed before following.
15. **Dialogs left open across a detach** (`hermes/ui/widgets/hooks.py:1517, 817`,
    `main_window.py:2718`): the hook dialog and the description dialog use objects the
    detach has removed (`AttributeError`, `KeyError`, deleted Qt objects). **Fixed**: an
    edit accepted after the hook is gone is only saved; the description dialog checks its
    table cell. Test `test_hook_edited_while_the_game_exits_is_only_saved`.
16. **Example templates on every start** (`hermes/db/repository/hooks.py:228-264`): a rename
    to an English name that a user template already has fails the UNIQUE constraint; the
    error is swallowed and examples are never created again. **Fixed**: a taken name stays
    German; translating and creating the examples fail separately and are logged. Test
    `test_an_english_name_taken_by_the_user_keeps_the_german_example`.

## Low

- `wine_gadget.py`: forwarded exports are not detected (`pe_export`); a gadget whose DLL
  loaded but never listened is retried with `LoadLibraryW`, which never runs its init again.
- `inject.c`: the HMODULE comes back through the thread's 32-bit exit code; a 64-bit base
  aligned at 4 GiB reads as NULL.
- `pointer.py`/`platform/linux.py`: modules keyed by basename (system32/syswow64 collide).
- `build.sh` runs `python3 -m ziglang` from PATH, not the venv; a relative
  `HERMES_INJECT_DIR` resolves differently in Python and in `build.sh`.
- `platform/windows.py`: `MEMORY_BASIC_INFORMATION` with `PartitionId` is wrong under 32-bit
  Python.
- `value_types.py`: `int(text, 0)` rejects leading zeros (`010`).
- `engine.js`: a JS pending entry can outlive a write whose `after` never ran; breakpoint
  sites call `Process.enumerateThreads()` while training is paused; the `fast` setup and the
  flush timer have no try/catch; the C range list is cut at 4096; C reads `uint64` as signed.
- `ptrace_hook.py`: one `ctx.state` for all hooks; `OverflowError` for large floats escapes
  `run()`; failed writes are swallowed.
- `trace.js`/`native_trace.js` duplicate the event protocol; `MethodMonitorWorker` and
  `MethodHookWorker` re-implement `AgentWorker`; `syncVotes` exists three times.
- `monitor.js`: the unmap watch detaches its listener inside its own callback.
- `mono/agent.js`: the batch thread runs CModule code after `finished=1`; `CreateThread`
  start routines are cdecl on ia32 (works because Wine restores the stack).
- `native_monitor.js`: `this` of 32-bit MSVC methods is in `ecx`, not `args[0]`.
- `method_call.py`: I8/U8 values above 2^53 are rounded.
- Dead code: `hermes/core/disassembler.py` and `hermes/hooks/loader.py` are empty;
  `effectiveAddress`, `registerValue`, `toPointer` in `engine.js` are unused;
  `recorded_summary` reads a key no agent sends.
- `main_window.py` is about 2950 lines with about 125 methods; candidates to split out: a
  scan controller, the address list, one attach/switch/detach path, a window registry.
- Localization: both files have the same 1019 keys and placeholders; `address_table.yes` is
  unused.

hook settings, log and cache paths and environment variables, the gadget's file name, Mono
hooks found again by their method, hook limitations (short jump, hardware breakpoints, C

`pyproject.toml` (extra `test`), `requirements.txt`, the docstring of
`_auto_select_backend` and two tooltips.

## C code: a folder of its own?

The project has two C files (`hermes/core/inject/inject.c`, `test_app/dummy_game.c`) and
about 1180 lines of C embedded in JavaScript as Frida CModules (`FAST_SOURCE` in
`hooks/engine.js`, `BATCH_SOURCE` in `engines/mono/agent.js`, `C_SOURCE` in
`features/trace.js` and `features/native_trace.js`).

A central `kernel/` folder is not recommended:

- Nothing runs in kernel mode; in a tool around ptrace and debug registers the name suggests
  a driver.
- Each CModule is coupled to its JavaScript through struct layouts and offsets; a central
  folder separates code that changes together. TinyCC cannot include local headers, so the
  modules could not share code there either.
- `inject.c` and `build.sh` are package data found through `HELPER_DIR`; outside `hermes/`
  a pip install would break. `dummy_game.c` is a test fixture.

Recommended instead: each CModule as a `.c` file next to its agent (e.g.
`hermes/hooks/engine_fast.c`), loaded with `load_agent_source`, with the few `${…}` values
prepended as `#define`s by the JavaScript, and a test that compiles every source as a
CModule in a local process. **Open.**
